# 产品需求与界面展示

## 问题如何进入产品设计

以下问题归纳依据原项目报告中的资源不足、信息核验和领养后续支持讨论。功能是相应设计方案，不表示已验证的运营提升。

| 需求问题 | 对应功能 | 本仓库展示 | 验收关注点 |
|---|---|---|---|
| 线索分散、缺少统一跟进 | 上报入口与结构化线索 | 02 救助线索 | 信息字段清楚，能看到处理状态 |
| 联系后不知道进展 | 未处理、等待回应、已处理 | 02 救助线索 | 状态有明确含义与下一步责任 |
| 领养信息需核实 | 动物资料与意向沟通 | 03 领养与回访 | 健康和性格信息标注核验状态 |
| 领养后支持衔接不足 | 回访记录与照护反馈 | 03 领养与回访 | 有回访内容、异常反馈和后续联系 |
| 日常照护知识获取不便 | 协作流程和科普 | 04 协作与科普 | 内容易读，图片符合社区与家庭场景 |

## 界面文件

- `ui/01.html`：项目首页。
- `ui/02.html`：救助线索上报与状态跟进。
- `ui/03.html`：领养与回访。
- `ui/04.html`：协作与科普。
- `ui/05.html`：项目问卷回收量与公开研究参考。
- `images/`：对应截图与本地配图，均无手机设备边框。

## 展示范围

约50条救助信息按负责人提供的近似口径。未处理30条为界面展示设定，界面列出的线索不是公开的真实求助记录。

负责人提供的经历包含机构对接与小程序试运行。本目录是本次重建的前端展示，未连接实际后台或机构系统，也未附当年上线日志。按钮和搜索不执行业务操作，截图不作为试运行成效取证。

## 试运行评估方案

将来接入真实后台时，分别记录：上报时间、首次响应时间、负责人、状态变更时间、结案依据与回访时间。可计算首次响应时长、线索处理率和约定周期内的回访完成率，并逐项注明分母和观察期。本仓库不为尚未提供的日志补写结果。
